# Guiltanas Control — démarrage 2026-10-29

## Mission
Unifier l'avancement de chaque projet de l'Atelier de Guiltanas indépendamment du nombre de conversations ChatGPT. Une conversation est une source historique, jamais la vérité unique.

## Règles non négociables
1. Chaque projet a une ligne de vie unique et des étapes identifiées.
2. Chats actifs, terminés, défaillants, archivés ou clôturés restent rattachables à plusieurs étapes.
3. "Clôturé" est un statut interne : il ne bloque pas ChatGPT. Ne jamais effacer un ancien chat avant récupération.
4. Les déclarations de l'assistant ne valent pas preuve de correction. Preuves : commit, test reproductible, résultat au clic, confirmation de l'utilisateur.
5. Un pourcentage n'est publié que si le dénominateur et les critères de validation sont explicites. Sinon : « non mesuré ».
6. Séparer les informations publiques et privées : aucun historique personnel ni secret dans ce dépôt public.
7. Distinguer état du code, état des tests et état de validation utilisateur.
8. Ne pas modifier Forge lors de la constitution du registre de suivi.

## MVP
- Page projets mobile-first.
- Une chronologie par projet, plusieurs chats attachés à chaque jalon.
- Journal des décisions, anomalies, preuves, commits et résultats.
- Statuts de conversations et procédure de récupération.
- Dossier de reprise transportable vers un nouveau chat.
- Lecture automatique d'un registre statique GitHub (sans API IA payante).

## Limite explicite
La récupération automatique et exhaustive des chats privés ChatGPT n'est pas disponible via GitHub Pages. La passation/import des conversations est distincte des données GitHub. Ne jamais annoncer un chat récupéré sans son contenu vérifié.
